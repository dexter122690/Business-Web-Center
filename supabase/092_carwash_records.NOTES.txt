CARWASH — deployment notes
Status: LOCAL PREVIEW ONLY. Owner chose "Local preview muna" on 2026-11-25.
Do not apply to production or publish this frontend without new approval.

Owner decision: carwash services are NOT entered again in Invoice Making.
New units default to Ongoing + Unpaid and may have a blank price.
Mark done works with or without a price. Reopen corrects accidental completion.
Work status never changes the receipt amount; editing a price preserves status.
An entered price is only a charge; it does not create income. Mark paid requires
a saved positive price and confirmation of the actual full-payment date, default
today (Asia/Manila). No payment before arrival or in the future is allowed.
The original row date remains arrival date. Paid price and arrival date are locked
to prevent silent changes to recorded income. Owner void remains audit-preserving.
Existing preview prices are NOT automatically converted to paid records.
This monitoring update is part of the unshipped 092 local-preview migration.

Timing: a new entry for today's Manila date captures server arrived_at on save.
The on-screen Manila clock is synchronized with the server, then advances using
a monotonic clock. Each ongoing unit shows elapsed minutes and seconds, updating
once per second without database writes. Done saves server completed_at plus
elapsed_seconds; these remain fixed across reloads, payment and metadata edits.
Reopen resumes from the ORIGINAL arrival (including the intervening time) and
the previous Done timestamp/duration remains in audit history. Timed arrival
dates cannot be edited. No exact arrival time is invented for old/backdated rows;
they show Not recorded. Timing never changes price, payment date, or income.

Monitoring cards above the entry table show Ongoing and Done counts for the
selected branch and arrival month. Counts follow saved work status, including
both paid and unpaid units, and exclude voided records. They refresh after
save/done/reopen/void, period changes, and branch changes; loading or unavailable
data shows a dash rather than a misleading zero. No new database writes are
needed for these counts.

Migration 092 adds only carwash_records and carwash_events, their RLS/select grants,
and two carwash RPCs. No existing records, invoice numbers, cash transactions,
inventory, payroll, expense or remittance records are changed. No imports occur.
Existing Invoice Making branch view/edit permissions are reused; only the owner
can void rows. Voided records are retained with before/after audit history.
Dashboard, daily/weekly/monthly income, executive Excel and print count only
explicitly confirmed active payments once, grouped as Carwash income, based on
payment date and selected branch/period. Arrival-month lists remain separate.
It does not add to the CIB cash-in-hand card (payment method is not collected).

Apply the additive migration before publishing the new frontend. Review the
production scope with the owner before running it. If not installed, the CARWASH
screen stays read-only with a setup message and old dashboard receipts continue.
To roll back the UI, deploy the previous frontend; preserve these new tables.
Never drop the tables to roll back once real records exist.
